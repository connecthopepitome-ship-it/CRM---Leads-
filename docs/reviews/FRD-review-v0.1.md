# FRD Review — SaleSphere CRM FRD v0.1 (Gate G2, testability & consistency)

| Version | Date | Author | Change |
|---|---|---|---|
| 0.1 | 2026-11-13 | Claude (independent QA reviewer) | Initial review |

**Scope:** `02-frd/FRD.md` v0.1, checked against BRD v1.0, the brief, STATUS.md, RTM.md, `templates/FRD.md` and CLAUDE.md §1/§5.
**What checks out:** FRD and RTM agree on all 91 FRs, every BR→FR link, the 59 FR→UC links and every priority (checked by script). All 31 BRs are covered and no Phase 2+ item is specified as Must. These worked examples are correct: FR-052 AC1–AC3 (₹21,240.00; IGST ₹3,240.00; +₹0.40 round-off), FR-005 AC1, FR-062 AC2, FR-061 AC1/AC2, FR-066 AC1/AC2, FR-071 AC1/AC3, FR-076 AC1, FR-075 AC2 and FR-090 AC1 (91 days > 90). Every template section is present.

## Findings

| ID | Severity | Location | Issue | Recommended fix |
|---|---|---|---|---|
| F-01 | High | FR-068 AC1, RULE-041 | The UPI `tr` example contradicts its own rule. The rule says "strip '/', keep '-'", so `INV/25-26/0142` → `INV25-260142`, but both examples show `INV2526-0142`. This is the test oracle for a payment payload. | Choose one transformation and give it as an explicit algorithm. Fix both examples. Add an AC for `pn` truncation at 50 chars and for URL-encoding of `tn`. |
| F-02 | High | FR-055 AC2, UC-007 E2 vs §6.1 E-09, RULE-003, FR-005 AC4 | The docs disagree on PDF failure after a number is allocated. FR-055 and UC-007 say the quote "stays in its previous state / not sent", which either burns a number (a gap) or leaves a draft holding one. E-09 says the document stays issued with "PDF pending". | Adopt E-09 everywhere: number allocation and status change commit together, and the PDF follows asynchronously. Rewrite FR-055 AC2 and UC-007 E2 to match. Add a negative AC to FR-065. |
| F-03 | High | FR-040 AC2, RULE-024, UC-003 A2, FR-041 (Should) | Exactly-once import is not guaranteed without write-back. When write-back is off or the ID column is deleted (E-30), the hash is the only identity. Editing a row changes its hash, so the row would be **re-imported**, which contradicts AC2. Two genuinely identical rows would also collide. | Define a stable row identity that doesn't depend on write-back, for example an Apps Script-stamped hidden row ID or timestamp column, or developer metadata. Otherwise make write-back Must and state the hash limits. Add an AC: "write-back off + row edited → no new lead". |
| F-04 | High | FR-088, RULE-054 vs RULE-012, FR-015, §7.2 AuditEntry (PII = Y) | DPDP erasure conflicts with the immutable audit log. Audit entries store before/after values (phone, email), and RULE-012 forbids editing them, so erased PII persists for 8 years. Daily backups (30 days) also keep erased data. | Store PII in audit entries tokenised or encrypted per person (crypto-shredding on erase), or exclude PII values from before/after. Add an AC that no erased value is retrievable via audit search or export. Document the backup-expiry window in §7.3. |
| F-05 | Medium | FR-088 AC1, RULE-053, RULE-054 | "Financial documents" is ambiguous. RULE-053 retains quotations for 8 years, yet FR-088 deletes a lead "with no quotes or invoices". It's unclear what happens to a lead that has only quotations or orders. | Define the set that triggers anonymise-instead-of-delete (e.g. issued invoice, CN, payment) and add an AC for a lead with a sent quote only. |
| F-06 | Medium | FR-005, RULE-003 | There is no GST numbering constraint: CGST Rule 46(b) requires ≤ 16 chars using only letters, digits, `/` and `-`, unique per FY. A configurable prefix plus padding can exceed this. FY selection for a back-dated document (dated 31-03, issued 02-04) is also undefined. | Add a series validation rule (≤ 16 chars, allowed charset) with a negative AC. State that the FY token comes from the document date and that the lock date applies (E-21). |
| F-07 | Medium | RULE-034, FR-051 AC2 | Place of supply is resolved as "shipping state, else billing" for every line. For B2B **services** (the pilot is a web developer), PoS is the recipient's registered location, so shipping-first can give the wrong CGST/SGST vs IGST. FR-051 AC2's default order ("lead's state or company's state") also differs from RULE-034's. | Split the rule by goods and services (services → billing/registered state). Align FR-051 AC2. Get CA review (R-009). |
| F-08 | Medium | FR-052, FR-020 | The tax engine has gaps that are high-risk but untested. There are no ACs for tax-inclusive rates, cess, spreading a document-level discount across lines and tax rates, multi-rate rounding (per-line vs per-rate summary) or decimal quantities. | Add worked-example ACs for each. These also feed NFR-018's ≥ 80 % domain-logic coverage. |
| F-09 | Medium | FR-064, FR-017, RULE-014 | Multiple GSTINs per company are allowed, but no FR says how an invoice picks the issuing GSTIN or branch. That choice drives intra/inter-state treatment, the series and the default UPI. | Add an issuing-branch field with a default and an AC. Otherwise restrict MVP to one GSTIN (the pilot needs only one). |
| F-10 | Medium | FR-068, FR-065, FR-003 AC2 | FR-068 re-renders the invoice PDF with a live QR amount, but FR-065 freezes issued values and FR-003 AC2 says issued PDFs are unchanged. The share flow also says nothing on which version is sent. A proforma has no "balance due", yet RULE-037 shows a QR for "requested advance"; its amount source is undefined. | Mark the payment block as a dynamic, versioned regeneration (original PDF kept). Define the source of the proforma advance amount and add an AC. |
| F-11 | Medium | FR-068, RULE-041 | Adding `tr` (and sometimes `tn`) to a deep link for a **personal** VPA is known to make some UPI apps decline or warn. The pilot is a freelancer, likely on a personal VPA (R-005). | Make `tr`/`mc` configurable per VPA type and add an acceptance test on the major UPI apps (GPay, PhonePe, Paytm, BHIM) in the test strategy. |
| F-12 | Medium | RULE-039, FR-085 AC1, FR-075 | Ageing buckets are "by days past due" starting at 0–30, but there is no "Not yet due" bucket. Not-due outstanding is either dropped or misfiled, so "buckets totalling outstanding" (FR-085 AC1) is not testable. | Add a "Not due" bucket (or define 0–30 to include it) and an AC with a not-yet-due invoice. |
| F-13 | Medium | FR-076 | The statement doesn't list TDS, advances/on-account credit or CN refunds as line types. Without a TDS line, the closing balance for the FR-071 AC3 case is wrong by ₹1,000. | F-14 | Medium | NFR-004 vs BR-008 | BR-008 requires leads within 5 minutes, but NFR-004 allows "interval + 1 min", i.e. 6 minutes at the 5-minute poll. | F-15 | Medium | FR-037, FR-038 | Scopes conflict with sheet selection. ## Verdict

**Pass with fixes.** There are no Critical findings, and coverage and traceability are sound. Fix F-01 to F-04 (High) and F-05 to F-24 (Medium) before G2 sign-off, because they would otherwise produce contradictory test oracles in Phase 8. The Low findings can be fixed in v0.2 or logged.
