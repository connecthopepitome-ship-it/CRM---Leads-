# HLD Review — SaleSphere CRM HLD v0.1 + ADR-001 – ADR-014 (Gate G6: NFR coverage and security)

| Version | Date | Author | Change |
|---|---|---|---|
| 0.1 | 2026-11-13 | Claude (independent QA reviewer) | Initial review |

**Scope:** `06-hld/HLD.md` v0.1 and ADR-001 – ADR-014. They were checked against FRD v0.2 §3.2, §6, §6.1 and §11, Solution Design v0.1 (G5), `templates/HLD.md`, `templates/ADR.md`, CLAUDE.md §1/§7 and the deferred items in FRD-review-v0.1.
**What checks out:**
- All 17 HLD template sections are present.
- All 14 ADRs follow the template (Status, Date, Deciders, Linked requirements, Context, Options, Decision, Consequences), and every stack override is recorded.
- HLD §10 gives each of NFR-001 to NFR-022 a mechanism and a verification method.
- The OWASP 2021 A01–A10 rows are all populated.
- The Argon2id parameters meet the OWASP minimum, and the dummy-verify timing equalisation is good.
- Deny-all rules, integer paise, `If-Match`/412, idempotency keys, expand/contract migrations and audit in the same transaction all match the FRD.

**Deferred FRD items:**
- **F-22 is closed** by ADR-010, which defines the match semantics (see H-05 for a data-model gap).
- **F-30 is closed** by `tokenEpoch` (60 s), but FR-010 AC3 still says 15 min (see L-01).
- **F-15 is only partly closed.** Picker + `drive.file` is stated, but ADR-008 adds an unnecessary `spreadsheets` scope (see M-06).

## Findings

| ID | Severity | Location | Issue | Recommended fix |
|---|---|---|---|---|
| H-01 | High | HLD §9; ADR-005 | The refresh cookie `__Host-rt` is given `Path=/api/v1/auth`. Browsers **reject** any `__Host-` cookie whose Path isn't `/`, so no session could ever be refreshed. | Use `__Secure-rt` with `Path=/api/v1/auth`, or keep `__Host-rt` with `Path=/`. Add an E2E assertion that the cookie is set. |
| H-02 | High | HLD §9, ADR-005, ADR-013 | Rotate-on-every-use plus family reuse detection has no concurrency design. The access token lives only in memory, so every reload, every extra tab and every service-worker Background Sync replay calls `/auth/refresh`. Parallel refreshes look like reuse and revoke the whole family, logging users out at random. | Make refresh single-flight across tabs (Web Locks or BroadcastChannel). Add a short reuse-grace window (e.g. 30 s) that returns the same successor token. Define how the service worker gets a token for outbox replay. Add test cases. |
| H-03 | High | HLD §4, §11, §14; ADR-003, ADR-006 | The edge→function trust model is one static shared header, `X-Edge-Key`, on a function with `allUsers` invoker. If the key leaks (logs, a CI artefact, a staff member), anyone can call `*.run.app` or `cloudfunctions.net` directly. That bypasses every edge rate limit, and the caller can spoof `CF-Connecting-IP`, which defeats per-IP limits and corrupts the IP evidence for quote acceptance (RULE-030). There is no rotation procedure. | Prefer IAM-only invoker: the proxy presents a Google-signed ID token (WIF or a narrowly scoped SA key in a Pages secret). Otherwise use an HMAC of method+path+timestamp with dual-key rotation. Trust `CF-Connecting-IP` only after the edge check passes. Add a login rate limit at the API backed by Firestore as defence in depth. Document key rotation in the runbook. |
| H-04 | High | HLD §4 (TASKS→API, JOBS→API), §11 | §11 says Cloud Tasks, Scheduler and Pub/Sub invoke "private endpoints", yet the diagrams route `email-send`, `sheet-writeback` and `push-send` tasks and job calls to the **public** `api` function. Internal routes would then be guarded only by the edge key. | Put task and job handlers in a separate `worker` function with no public invoker, or verify the Google OIDC token in-app (audience + SA email) on `/internal/*`. Have the edge proxy block `/internal/*`. |
| H-05 | High | HLD §8.2, §9; ADR-011; RULE-011 | Scope filters use `ownerId in teamMembers`, but `quotations`, `orders`, `invoices`, `payments` and `files` have **no `ownerId`** (only `customerId` or `partyRef`). Own- and Team-scoped lists, search, aggregation tiles and exports for Sales Exec and Sales Manager (§3.2) cannot be expressed as Firestore queries. Invoices, quotations, orders and payments also lack `searchTokens`, so FR-083 AC2 ("0142") can't be served, and contacts (a subcollection) need a collection-group index. Customers lack a `(searchTokens, ownerId)` index. | Denormalise `ownerId` (and `teamId`) onto every scoped collection. Define fan-out on reassignment (FR-032). Add `searchTokens` to the document collections and contacts. Publish a query and index catalogue per screen in the HLD or LLDs, including the composite indexes for `in` + `array-contains` and `in` + `orderBy`. |
| H-06 | High | HLD §10 NFR-006, §14; SD §7; FRD §7.3 | Firestore **scheduled daily backups keep at most 7 days** (14 weeks only for weekly backups). "Daily backups kept 30 days" can't be configured, and RULE-054's "≤ 30 days in backups" statement depends on it. | Choose one: (a) daily backups (7 d) plus weekly backups (≥ 5 wk); or (b) a scheduled managed export to an `asia-south1` GCS bucket with a 30-day lifecycle, which needs a third scheduler job (costed). Consider PITR (7 d). Align FRD §7.3, RULE-054 and SD §7 through a CR. |
| H-07 | High | HLD §10 NFR-003; ADR-009 | ADR-009 verifies the PDF p95 ≤ 5 s "measured warm", but the NFR has no warm-only qualifier. Chromium cold starts are 3–6 s, and at pilot volume (Solo, a few documents a day) almost every render is cold, so the Must NFR is unverified and probably failed. | Measure p95 including cold starts. Then either set `minInstances: 1` on `pdf` (costed), or raise a CR so NFR-003 targets warm renders and adds a separate cold bound. Note that the user is not blocked because rendering is async (E-09). |
| H-08 | High | HLD §9, §13; NFR-010 | pino redaction doesn't reach **platform request logs**. Cloud Run logs the full `requestUrl` automatically, which will capture share tokens (`/public/share/<token>`), search terms in GET query strings (phones, names) and sync IDs. The `route` field may also hold raw paths. Redaction paths are listed as top-level keys only. | Send search through POST or keep PII out of query strings. Log route templates, not raw paths. Add a log exclusion or sink filter for `run.googleapis.com/requests`, or strip the URLs. Use wildcard redaction (`*.phone`, `req.headers.cookie`, …). Add a test that greps staging logs for seeded PII. |
| M-01 | Medium | HLD §4, §9; ADR-006; FR-008, FR-027 AC4 | The edge rate-limit mechanism is unspecified. Isolate memory isn't global, KV is eventually consistent, and Free-plan WAF rate rules are limited and need the client zone on Cloudflare (the HLD uses only a CNAME). A 20/IP/min limit on all of `/auth/*` (including refresh) will trip on shared office NAT. | Name the mechanism (Workers Rate Limiting binding, a WAF rule, or a Firestore counter in the API). Limit only login and 2FA to 20/IP. Add per-source 60/min for forms and hooks, plus a cap on sheet pings. |
| M-02 | Medium | HLD §9 A05, NFR-009 row | The CSP feasibility claim is vague ("nonce-less hashed bundles"). Several parts aren't covered:<br>• Radix/shadcn set inline `style` attributes.<br>• Picker needs `apis.google.com` scripts and `docs.google.com` frames.<br>• FCM needs `*.googleapis.com` in `connect-src`.<br>• QR codes need `data:` in `img-src`.<br>• A shadcn theme script, if used, is inline.<br>• `_headers` does not apply to Pages Function or API responses. | Publish the exact policy. Allow `script-src 'self'` with external scripts only (vite-plugin-pwa `injectRegister: 'script'`). Use `style-src 'self' 'unsafe-inline'`, which NFR-009 allows because it bans only inline scripts. Add explicit Google hosts and `frame-ancestors 'none'`. Set headers on API and proxy responses in the proxy. Assert them in E2E. |
| M-03 | Medium | HLD §9; SD §8 | CSRF isn't covered in the HLD. SD §8 promised "SameSite plus a custom header check". The login, logout and refresh endpoints are cookie-bound, and the public form needs **CORS** for the client's website origin, which contradicts "no CORS needed". | Require a custom header (e.g. `X-Requested-With`) plus an `Origin` check on cookie endpoints. Define a CORS allow-list only for `/public/forms/*`. Add Cloudflare Turnstile (free) as the bot control, since an `Origin` header is forgeable outside browsers. |
| M-04 | Medium | HLD §9; ADR-005; NFR-007 | ASVS L2 V3.3.2 expects re-authentication about every 12 h or after 30 min idle. RULE-008 gives a 30-day sliding refresh with no absolute lifetime. The JWT carries `role` and `scope`, but `tokenEpoch` is bumped only on logout and deactivation, not on role, team or permission changes. 2FA design gaps: no single-use binding for the password-OK step token, no prevention of TOTP code replay, and lock-check ordering per FR-008 AC2 is unstated. | Add an absolute session lifetime, or record the ASVS deviation (A-xxx) for sign-off. Bump the epoch on role, team and permission changes. Specify the 2FA step token (≤ 5 min, single use), last-used-step replay protection, and verifying the password before revealing a lock. |
| M-05 | Medium | HLD §9 "Secrets", §11; SD §9 (A-028) | "Deploy-only, no data access" isn't enforced technically. SD grants the CI SA Secret Manager **admin**, which can read JWT keys and the Google refresh token. Anyone who can deploy functions can run code as the runtime SA. There is no runtime service-account and IAM matrix, and the default compute SA has Editor. | Add an IAM table: a dedicated runtime SA per function with minimal roles, and a CI SA with `secretmanager.secretVersionAdder` only. Enable Data Access audit logs. State the processor trust honestly in the DPDP mapping and client agreement. |
| M-06 | Medium | ADR-008; HLD §7 INT-001/002 | F-15 is only partly closed. The Sheets API accepts `drive.file` for a picked file, so the sensitive `spreadsheets` scope is unnecessary and over-privileged. Picker also needs a browser-side OAuth access token, a developer key and `setAppId(projectNumber)`, which conflicts with FR-013's "browser never accesses Drive directly". Every install has its own OAuth client, so verification is needed **per client project**. | Drop `spreadsheets`. Define a short-lived `drive.file` access-token endpoint for Admins only (no refresh token) and a referrer-restricted Picker key. Record the FR-013 exception. Add per-install consent and verification steps to R-001/A-024. |
| M-07 | Medium | ADR-009; HLD §9 A10 | PDF SSRF and injection controls are a single sentence. The design doesn't specify request interception, disabled JavaScript, `file://` blocking, how the logo is inlined, or sanitising of Admin-edited templates and T&C (FR-021). | Specify: `setJavaScriptEnabled(false)`; abort every request that isn't `data:`; fetch the logo server-side with size and MIME limits and inline it; render templates with auto-escaping; allow only a safe Markdown subset for T&C. Add negative test cases (e.g. `<img src=http://169.254.169.254>`). |
| M-08 | Medium | ADR-004 vs SD §7; ADR-010 vs SD §7; HLD §4 | The documents disagree on which mechanism runs:<br>• **Customer totals:** SD says triggers; ADR-004 says "in the same transaction (not only by triggers)", which risks double counting.<br>• **Search tokens:** SD says a trigger; ADR-010 says the domain writes them.<br>• **Triggers function:** ADR-001 and SD mention a Firestore-triggers function, but HLD §4 omits it. | Pick one mechanism for each (recommended: in-transaction totals and domain-written tokens, with no triggers). Update SD by note or CR, ADR-004 and the HLD §4 diagram and container table. |
| M-09 | Medium | HLD §14 timeouts; NFR-010, FR-023, FR-085 | The edge→api timeout (30 s) is shorter than the api timeout (60 s). Excel exports at 50k rows, 5k-row imports and DPDP erase (Drive deletes, ≤ 5 min) can exceed 30 s. The `api` function has 512 MiB at concurrency 40, while uploads are up to 25 MB and exports are built with exceljs. | Run long operations as async jobs with status polling and a downloadable result. Set `cpu: 1` explicitly (concurrency > 1 needs ≥ 1 vCPU). Stream uploads, size memory per worst case, or cap concurrency on heavy routes. |
| M-10 | Medium | HLD §9; CLAUDE.md §7 | There is no per-endpoint trust classification. Five auth mechanisms (user JWT, share token, API key, HMAC, OIDC) plus unauthenticated health and forms have no table mapping route groups → authn → authz → rate limit → audit. Share-link access logging (RULE-049) has no store in §8.2. | Add an endpoint-group security matrix to HLD §9 and an `accessLog` collection or subcollection with its retention (link life + 1 y). |
| M-11 | Medium | HLD §10 NFR-007 | A ZAP **baseline** scan is passive and unauthenticated, so it can't evidence ASVS L2 access control or the "no High/Critical" Top-10 claim. | Add an authenticated ZAP API scan driven by the OpenAPI spec, an automated IDOR/scope matrix test (every route × role × scope), and an ASVS L2 checklist sign-off artefact. |
| M-12 | Medium | HLD §9 Compliance, §13; NFR-010 | NFR-010 says "all personal data stored **and processed** in `asia-south1`". Cloudflare (global edge), FCM, Gmail/Drive (consumer, global) and Cloud Logging's `_Default` bucket (location `global` unless set) all break that. The DPDP Rules 2025 also require 1-year retention of security logs and 72 h breach intimation, and the HLD covers neither (Logging is 30 d). | Set the log bucket region to `asia-south1` at provisioning. Raise a CR to scope NFR-010 to the system of record and list the sub-processors. Add a breach-response procedure and decide log or audit retention ≥ 1 y (confirm with counsel). |
| M-13 | Medium | HLD §14 backup/restore; RULE-054 | Restoring a backup brings erased people back, and the runbook doesn't re-apply erasures. | Keep a non-PII erasure ledger (hashed phone/email + record IDs) and replay it after every restore. Add this to the restore drill. |
| M-14 | Medium | HLD §8.2, §14; E-19 | A bulk reassign of 500 leads, with audit, in one transaction risks contention, size limits and timeouts. The `jobs` function (Pub/Sub, at-least-once, 540 s) has no lease, so overlapping or duplicate ticks can double-send reminders. | Chunk bulk operations (≤ 100 per transaction) and return per-record results. Add a Firestore lease document per job type and a dedupe key per reminder. |
| M-15 | Medium | ADR-013; NFR-021 | The ≥ 7-day outbox depends on the platform. Safari evicts script storage after 7 days without use unless the app is home-screen installed, and Background Sync is unsupported on Safari and Firefox. | Call `navigator.storage.persist()`. Require or prompt for install on iOS. Make focus or online replay the primary path. Test on real iOS 16.4+ and Firefox. |
| M-16 | Medium | HLD §10 NFR-002 | The k6 test hits a warm staging service, so the p95 cold start ≤ 3 s target has no verification. | Add a scripted cold-start probe (after scale-to-zero, N samples) with a `cold_start_ms` log metric. |
| L-01 | Low | ADR-005 vs FR-010 AC3 | The HLD's 60 s forced-logout window is stricter than FR-010 AC3 (≤ 15 min), so the test oracles diverge. | Update FR-010 AC3 to "≤ 60 s" through a CR or note in the RTM. Close F-30. |
| L-02 | Low | HLD §10 NFR-001 | Lighthouse can't measure INP (lab runs report TBT) or field p75. | Use Playwright with the web-vitals INP on scripted interactions, or note the lab proxy with a TBT budget. |
| L-03 | Low | HLD §13 SLO/alerts vs NFR-004 | The SLO "Sheet import ≤ 5 min for 99 %" and the alert "sync lag > 10 min" are looser than NFR-004 (≤ 1 min p95 for webhooks, interval + 1 min for polls). | Align the SLO with NFR-004 and alert on lag > 5 min. |
| L-04 | Low | HLD §9 A03 | The CSV/Excel injection guard misses leading Tab and CR. Prefixing every `-` also corrupts negative numbers if applied to numeric cells. | Prefix `' ` on text cells starting with `= + - @ \t \r`. Write numbers as numeric cells. Add test cases. |
| L-05 | Low | HLD §9 OWASP | The mapping uses the 2021 edition. OWASP Top 10:2025 adds Supply-Chain (A03) and Exceptional Conditions (A10). Upload content checks (magic bytes, `Content-Disposition: attachment`) and mass assignment (Zod `.strict()`) aren't mapped. | Map to the current edition and add those controls. |
| L-06 | Low | HLD §10 NFR-005, §13 | Health checks Google connectivity, so a Google outage or revocation would count as downtime. The uptime check covers the API only, not the Pages app shell. | Split `/health/live` (counted for the SLO) from `/health/deps`. Add an uptime check on `/`. |
| L-07 | Low | HLD §10 NFR-019, §12 | The rollback covers function code only. It doesn't cover the Pages deployment, Firestore rules or indexes. | Define a rollback for all three (Cloud Run revision traffic, Pages rollback, the previous rules artefact) and include it in the drill. |
| L-08 | Low | ADR-010 | Taking 50 results from `array-contains` on the first term and then refining in memory can miss true matches for common prefixes under All scope. | Query the most selective token (the longest or numeric one) and paginate until there are 50 refined hits or a read cap is reached. Document the limit. |
| L-09 | Low | HLD §7 INT-003 | The HMAC must be computed over the raw body (`req.rawBody`). The per-sheet secret is readable by every sheet editor, which is acceptable only because the ping is a hint. | State both, and rate-limit pings per `syncId`. |

## Verdict

**Pass with fixes.** There are no Critical findings. The architecture fits the approved Option A, and every NFR has a mechanism and a verification method. Fix H-01 to H-08 in HLD v0.2 before G6 sign-off:
- H-01 would break login outright.
- H-06 can't be configured.
- H-05 blocks RULE-011 scope enforcement on finance documents.
- H-03, H-04 and H-08 are security and privacy gaps.

Resolve the Medium findings in v0.2 or carry them into the named LLDs (identity, platform, insights, documents) as tracked items. Raise CRs for NFR-003, NFR-010, RULE-054/§7.3 and FR-010 AC3. The Low findings can be logged.
